## Measured results

`RAYON_NUM_THREADS=16 taskset -c 0-15 target/release/examples/frontend_derived_compare 7` alternated seven measured scan/indexed rounds after a warmup on each path. All 200 complete ordered IDs, counts and truncation flags matched. Derived-only index build took 146.209 ms; median scan query was 133.961 ms (132.928–135.447 ms), and median indexed query was 1.847 ms (1.732–1.943 ms). Source reads and parses fell from 20,101 to 201 per query. The separate fused build of both stored-text bigrams and derived typed postings took 151.772 ms and performed exactly 20,100 reads and 20,100 parses; its complete result also matched the scan. `frontend-derived-fused.json` contains every sample and ordered ID; the adjacent manifest records the command, hash and fixture identity. The earlier `frontend-derived.json` is an intermediate pre-fusion control, retained separately.

The normal JSON control used `run_paired_json_extension.py` with three alternating process pairs, seven rounds per process, 50 loaded cases, ASCII encoding and separate 0/64 MiB query-cache budgets. All case signatures matched in every pair, with identical scans, source reads and parses. In the final `json-50-fused/summary.json`, the median of paired medians had a maximum positive delta of +0.229 ms at cache 0 (case 11, `year >= 1800 && year < 1805`, 4.622 ms reference median) and +0.138 ms at cache 64 (same case, 4.438 ms reference median). The median case delta was +0.010 ms and -0.001 ms respectively. The largest negative deltas were -1.199 ms and -0.045 ms. Every raw stdout, stderr, command, exit status and per-case sample is retained under `json-50-fused/`. `json-50/` preserves the earlier, pre-fusion paired run, which also matched all signatures and work counts.

Case 11 was sampled again alone with five alternating pairs and 15 rounds. The first attempt failed before any timing because the one-case workload retained ID 11; the runner requires sequential IDs. The failed command output is kept in `case11-paired/`; the corrected one-case workload and complete results are in `case11-paired-v2/`. The isolated cache-off paired deltas were +0.063, -0.014, +0.090, +0.014 and +0.046 ms (median +0.046 ms); cache-on median delta was -0.004 ms. Work counts remained equal. The full-workload case remains a small positive timing observation, but the isolated result does not support a material scanner regression.

## Correctness and limits

External-consumer tests cover missing/null/multiple values, exact year ranges, sort cardinality errors, mixed text/derived OR coverage, empty candidates, complete ordered-page cache reuse, request freshness, refresh invalidation, malformed extraction, and all-or-nothing publication after a failed fused build. The fused test asserts one read and one parse per selected source. `cargo test --locked --workspace --all-targets`, `cargo clippy --locked --workspace --all-targets -- -D warnings`, and `cargo test --locked -p objekte-bench --features index-timings,allocation-profile --all-targets` passed. Changed Rust files pass rustfmt with `blank_lines_upper_bound=2`. The whole-workspace spacing command still reports the same seven pre-existing hunks in five untouched files; see `spacing-final-status.json` and logs. Test and Clippy logs are retained here.

This is a targeted stage control, not Gate 5 or final acceptance. Selected postings are process-local and absent from snapshots. The custom frontend still sorts with a bounded heap instead of traversing the derived B-tree in order. Provider records remain outside the legacy JSON picker, typed postings and snapshot format; legacy text/JSON queries still reject provider-backed collections. The final full benchmark matrix and large-corpus source-oracle runs remain open.
