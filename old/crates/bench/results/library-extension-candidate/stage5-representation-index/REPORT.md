## Results

The new frontend control ran `RAYON_NUM_THREADS=16 taskset -c 0-15 target/release/examples/frontend_index_compare examples/musenalm 7`. It used the existing Markdown renderer on `contents.annotation`, disabled the query cache, warmed both paths once, and alternated scan/indexed order for seven measured rounds. The explicit index built 133,948 selected sources in 3,728.844 ms. The `Goethe` request returned the same complete, ordered 284 IDs, count, and truncation flag by both paths. Median query time was 3,134.573 ms for the scan and 9.513 ms with the index; source reads and parses were 133,949 versus 326. The indexed path reported 325 candidates. The index-build time and query times use warm filesystem caches and are not cold-storage measurements. Full raw samples, ordered IDs, command, executable hash, and stderr are in `frontend-index.json` and `frontend-index-manifest.json`.

The prior-stage binary and this candidate were paired in three alternating process pairs, each with seven query rounds and separate 0/64 MiB query-cache budgets. All 50 case signatures matched for each pair, and every case had identical scan, source-read and parse counts. At cache 0, the largest positive median-of-paired-median delta was +1.028 ms for case 30 (`created < updated`, 115.609 ms reference median); the median case delta was -0.037 ms. At cache 64 MiB, the largest positive delta was +0.787 ms for case 50 (`data.description ~ 'Musenalm'`, 117.300 ms reference median); the median case delta was -0.024 ms. The largest negative case deltas were -0.462 ms and -0.188 ms respectively. The spread and all per-case deltas are retained in `json-50/summary.json`; these small positive deltas do not establish a reproducible slowdown, and no work-count increase appeared.

## Correctness and scope

The workspace tests, Clippy and bench tests with `index-timings,allocation-profile` passed after the stage change. Changed Rust files pass rustfmt with the repository's `blank_lines_upper_bound=2` configuration. The whole-workspace spacing check still fails only in five files unchanged from the starting revision; its output is saved as `spacing.stdout.log`. External-consumer tests compare scan and indexed ordered rows, counts, projections and identities over mixed JSON/Markdown sources; cover AND/OR/NOT, empty hints, Unicode and array value boundaries, source edits, refresh invalidation, malformed data, freshness modes, cache-disabled rejection and fallible operators that must retain exact error behavior. The representation posting is engine-owned and explicitly built; the default JSON picker path is unchanged when the API is unused.

This is a targeted stage control, not Gate 5 or final acceptance. The representation posting is process-local and absent from snapshots. Provider records are still absent from legacy `FilePicker` postings and snapshots, and legacy JSON/text queries over provider-backed collections still report unsupported. The custom frontend still uses a bounded heap for derived ordering; it does not yet consume an indexed derived sort. The full Phase 0 performance matrix, large-corpus build/restore controls and independent source oracles have not been repeated for this stage.
