## Representation and selection

`PostingIndex` now owns an optional sparse map from seven structural keys to Roaring bitmaps: any selected null, nonempty, string, number, array, object and empty object. It remains inside the existing per-field posting and segment persistence lifecycle; there is no separate field-state column, synthetic path, second value dictionary, or construction pass. The old singleton-null bitmap keeps literal-null equality semantics. Any-null is separate because a path can select both null and text. `NonEmpty` is a positive fact because a mixed empty/nonempty selection cannot be represented by subtracting empties from presence. String includes logical IDs; temporal values retain exact presence/nonempty behavior without a new type modifier. Empty strings use the existing exact empty-string value posting, empty arrays use exact length-zero posting where the selection domain agrees, and numeric zero uses ordinary scalar values. Empty object needs its own fact. Missingness is computed inside the known active coverage domain. A sparse `empty_selections` exception bitmap preserves legacy path-presence semantics through an empty ancestor while making `:exists` exact on selected values.

The existing effective selection policy decides allocation. A declared `indexed` field receives new facts; an explicitly inferred field receives them only after admission as `Built`. Provisional facts follow the existing observation budget and are discarded if admission fails. Legacy structural-only fields keep their prior presence, length, and empty-string acceleration but receive no new type-fact map. Unindexed, prohibited, sort-only and named transformed indexes do not silently receive logical-field state facts. Inference remains off unless configured; no dynamic-key scan adds new indexes automatically. A 64-file fixture with one distinct dynamic key in each file retained exactly one explicitly selected field posting, made that field's type predicate source-free, and evaluated an unselected key from source.

Construction classifies the already borrowed selected values during the existing posting visit. Inference records facts during its existing bounded observation traversal, then transfers only admitted facts. Batch merge, compaction/remapping, validation, and snapshot serialization carry the new bitmaps. Both snapshot versions were bumped for the changed serialized shape; incompatible older caches follow the existing rebuild path. The `IndexCatalog` assessment remains the sole capability and cost model for declared and inferred accesses. It applies exact bitmap set operations within covered active records, keeps uncovered records for residual evaluation, and restricts explicit array selectors and correlation contexts to source evaluation where independent facts would not prove a shared element.

## Query correctness and latency

The completed 220-case manifest ran under four profiles (ASCII/Unicode × cache-off/warm), five repetitions each: all 880 case/profile rows passed. A strict predecessor comparison independently checked the unchanged first 206 cases in 824 rows: status, count, returned page digest and source opens matched or improved; no previously source-free case gained a source open. The final 220-case run also matched all 206 predecessor result digests. The 26 new Plan 2/Plan 3 cases Q195–Q220 matched the independent `search_reference` source evaluator in count and page hash. Q207–Q220 cover selected nested paths, empty arrays, type negatives, presence, nonempty and Boolean compositions; all 56 case/profile rows opened zero source files. Cache-off ASCII medians range from 0.014 to 0.362 ms for those 14 cases, including broad 133,948-record and restricted seven-record answers.

The pre-existing Q108/Q116/Q120 cases remain source-free, with 2,684/70,428/42,700 matches and cache-off ASCII medians 0.031/0.089/0.070 ms. Newly exact Q198–Q201, Q205 and Q206 also become source-free. Q195–Q196, Q202 and Q204 retain source fallback for unindexed contributors; Q203 retains it for an explicit selector. This is intentional capability behavior. Across the first 206 queries, the sum of cache-off ASCII medians was 1,487.878 ms in Plan 2 and 1,228.535 ms in the final Plan 3 run; Unicode was 1,476.007 to 1,235.934 ms. These sums are descriptive, not an aggregate throughput benchmark. The Q004 Unicode apparent outlier was investigated with five alternating isolated pairs of 15 repetitions each: median of per-run medians was 10.040 ms before and 9.937 ms after, so it did not repeat as a >10% and >0.5 ms regression. [Per-query tables and outlier runs](../../../bench/results/indexed-field-structural-postings/README.md) are retained.

Nine additional fresh-process foreground construction runs cycled idle, Q108/Q116/Q120 foreground and held-early-view modes three times. Median full build was 919.013/939.766/915.788 ms respectively; foreground was +2.26% versus idle in this separate campaign. Each foreground process completed 891–942 queries with zero query source opens, 22.4–27.0 µs median latency and 61.0–65.9 µs p95. First nonempty results arrived 281–289 ms after the query worker began. All nine made 148,486 construction reads/parses. The held view did not create an accumulating second full index in these three runs (median HWM 574.063 MB versus idle 571.732 MB). These measurements use Plan 1's same fixed workload and do not replace the paired no-query acceptance test.

Tests include source-oracle truth tables, a deterministic 96-record mixed-value sample with AND/OR/NOT, a 64-key sparse-selection fixture, partial publications and unknown coverage, inferred admission/rejection, snapshot/compaction, validation, and explicit replacement/move/delete/add with source-free state membership. `cargo clippy --workspace --all-targets --locked` exited zero with 211 underlying warnings, the same count and distribution as the Plan 2 baseline. `git diff --check` passed. `cargo fmt --all --check` and `python3 scripts/format-rust-spacing.py --check` still flag inherited workspace style drift; the final rustfmt file set matches all 95 flagged Plan 2 files with no candidate-only file. The native desktop built, launched in the task-owned headless Wayland session, and opened the five-file fixture; the task-owned app and pointer server were cleaned up. Plan 2's [native predicate UI exercise](../../../bench/results/boolean-field-predicates/2026-11-13-client-smoke/README.md) remains applicable because Plan 3 changed no UI code. CLI process and TUI renderer tests passed within the workspace suite.

There is no object/array equality literal syntax in FILTER; the supported state predicates use the exact new facts. Explicit array selectors and same-element correlation still use source evaluation when the independent posting facts cannot prove the relation. The direct-build attribution profile is a single noisy diagnostic pair, and the native Plan 3 smoke confirmed opening the fixture but did not re-run Plan 2's full builder interaction. No in-scope correctness or acceptance failure remains.
