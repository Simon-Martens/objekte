## Outcome

The retained changes remove identifiable per-key and per-posting copies, repeated sealing work, source-query grouping allocations, and repeated maintenance partition work. In the final paired measurements against `e397f8f3`, complete construction is effectively unchanged; query medians improve about 1–1.5% across the three modes. The original pre-hybrid construction and query gap remains. The user explicitly relaxed the earlier millisecond/percentage performance targets and asked for improvement and baseline ratios to be documented. Correctness and durability requirements remain in force.

Its query median geometric means are 1.067× memory, 1.121× resident, and 1.126× on-demand against the archived original 440 rows. These cross-campaign ratios show the remaining gap; they are less controlled than the fresh paired `e397f8f3` comparison. The original snapshot save and new managed flush differ in durability steps, so their 352.01 ms and 253.82 ms medians are descriptive, not an equivalent-cost ratio.

## Changes and package disposition

| Package | Status and evidence |
| --- | --- |
| 1. Posting operations | Implemented in `fa8394f6a7`: cached operands are borrowed outside cache locks for intersections and unions; decoded ownership transfers to cache. The serialized fallback remains fallible and commits the result only after success. Focused equivalence, corrupt-input, cache-hit/eviction and concurrent-reader tests pass. In an isolated pre-union-extension probe, medians rose 1–2% while p95 fell 5–6%; the final combined suite is the acceptance evidence. |
| 2. Validation and cache synchronization | Measured, rejected two prototypes, and retained the bounded lazy mutex map. An eager per-descriptor `OnceLock` map added about 20 MB ASCII and 54 MB Unicode RSS without stable latency gain. A narrow `RwLock` experiment increased focused warm on-demand median 4–6% and p95 6–8% in two reversed process orders. The existing constructed-reader proof bypasses the external map; external first access remains once-only and bound to its dictionary/domain. Separate cache mutex wait/acquisition counters and independent-query contention measurements were not completed; no synchronization design change is claimed. |
| 3. Borrowed typed comparisons | Implemented in `7279796a35`: point and lower-bound probes compare borrowed encoded scalar keys and decode descriptors on selected entries. Generic checked fallback remains. Ordered-block differential tests pass. |
| 4. Leaf key arena | Implemented in `09154558b7`: reusable encoded-key arena and offsets remove the per-key `Vec` allocation, including fixed-width `u64` grams; sparse boundary keys remain owned. Portable leaf format and round trips are unchanged. The isolated seven-pair whole-build median was 1.0039×, so no independent whole-build speedup is claimed. |
| 5. Direct memory posting serialization | Implemented in `003297081a`: checked posting bytes append to the final constructed payload vector; file streaming keeps scratch. The scratch-to-final copy is removed on the memory path. Codec tests compare emitted bytes and reopening. A combined early seven-pair probe was 0.9832× complete build, but attribution to this package alone is unavailable. |
| 6. Sealing passes | Implemented in `376dd75b61`, `2ba53f3a20`, `ceba166b72`: constructed bindings and counts are carried from encoding, fallback domain reused, fresh gram filters populated as keys are written, and external gram filters populated during mandatory leaf validation. External validation remains checked; constructed and external no-false-negative tests pass. The generic sealed estimator has no measured production caller and was left unchanged. |
| 7. Source-query allocation | Implemented a bounded single-range inline representation in `9835f0c4e7`. Reversed focused Q006/Q007 pairs improved medians roughly 6–8% and p95 roughly 6%; full-suite source-heavy cases also improved with unchanged file opens/read bytes. Additional reusable read buffers and winning-payload retention are profile-gated: Q006/Q007 each open 148,486 source files and read 193,297,230 bytes, with zero selected-payload rereads, so retaining payloads would add memory without removing the dominant reads. |
| 8. Bigram contribution validation | Profile-gated and deferred. Detailed profiling at `9835f0c4e7` measured 0.939 ms total bigram validation within 1,096.319 ms readiness (<0.1%). A new validated-contribution ownership type would add risk for little measured gain. The profiler did not expose a separate examined-block count. |
| 9. Publication and maintenance | Implemented in `980a8831dc`, `5ca0598b0d`, `23c4b1a588`, `82cc05c21c`, `3bd8b74d79`: one-pass partition sorting/domain/inference scatter, consuming fresh static sealing, reuse of unaffected shard groups, and bounded explicit compaction batches. A normal partitioned-root batch has 32,768 source-record, 64 MiB input, 128 MiB estimated temporary, and one-second between-shard limits, with one oversized-shard progress exception. The report exposes remaining retired slots and charged work; verified-update compaction requires completion or falls back. The older base-containing path is not batched, and temporary bytes are estimates rather than allocator peaks. |

No per-allocation profiler was run on the final binary. The removed allocations/copies above follow directly from changed ownership and buffer paths, while the measured RSS and elapsed times are the whole-process evidence. A prior Massif diagnostic found 44 MiB posting-vector capacity slack before these changes; it is not a measurement of the final build. The sealed decoded-posting cache remains bounded per segment at `min(encoded segment bytes / 20, 8 MiB)` and is charged more conservatively than serialized size. Full-query after-run RSS was 553.77 versus 572.13 MiB (candidate/start, ASCII memory) and 1,013.84 versus 1,064.33 MiB (Unicode memory); these are different from after-build paired RSS and include query/cache state.

## Representative queries and tails

Q006/Q007 medians improved 3–7% across the final memory, resident, and on-demand runs with identical source-read counts and digests. Q175 ASCII full-run memory p95 was **6.966 versus 5.406 ms** (candidate/start), and Q167 ASCII on-demand p95 was **9.119 versus 6.452 ms**. Seven alternating focused 30-repeat pairs did not reproduce those spikes: median of per-run p95 for Q175 ASCII was 5.063 versus 5.312 ms in memory and 5.343 versus 6.301 ms on-demand; Q167 ASCII on-demand was 6.581 versus 6.964 ms. The full-run spikes remain in the raw record. Individual short-query tails vary materially with process scheduling and cache state; the evidence does not justify declaring all representative tails at original-baseline parity. Q175 ASCII original-baseline p95 was 3.71 ms in the archived campaign.

## Storage, maintenance, and validation

Seven warm opening-through-Q001 pairs found on-demand ASCII open medians 374.609→373.311 ms and Unicode 384.687→378.669 ms (start→candidate). Q001 first-query medians were 10.812→10.730 ms ASCII and 13.342→11.232 ms Unicode. Fully resident opening was slightly slower: ASCII 437.152→442.608 ms and Unicode 459.064→463.872 ms; first-query medians were close. The opening runs reported zero source parses.

Three cold-index pairs used `POSIX_FADV_DONTNEED` on only the `.idx` and catalog `.bin` files. `fincore` confirmed zero cached bytes before each process, from 228–260 MB cached beforehand. Source-file pages were not evicted. Candidate/start cold ASCII opening varied by pair (465/403, 459/409, 408/445 ms); this small sample does not establish a cold-opening gain. `time` recorded 35–38 major faults and about 241 MB candidate versus 276–279 MB start filesystem input per process. After the two alphabet queries, 228 MB of index files was cached again. This is file-scoped cold-index access, not a cold-source benchmark.

Under a real `MemoryMax=512M` user-systemd cgroup, both revisions opened and ran Unicode Q006 and Q175 for 30 repetitions in on-demand and fully resident modes with matching digests. Candidate/start Q006 median was 163.70/167.61 ms on-demand and 162.64/170.00 ms resident; Q175 was 3.379/3.542 ms and 3.855/4.194 ms. Maximum resident set was about 325 MB on-demand and 380 MB resident; recorded major faults were 0–1. Earlier `RLIMIT_AS` probes failed during thread creation even at 2 GiB and are not used as memory evidence.

An independent inference-enabled incremental build completed eight searchable batches; five checked query digests matched `e397f8f3`. Complete readiness was 2,495.9 versus 2,536.2 ms in one unpaired process each. A disposable 5,000-file, 178-revision stress run covered add, update, move, delete, 32 repeated updates, reconciliation, compaction, rebuild, flush, reopen, and a pinned revision-1 reader. No concurrent query probe errors occurred; 167 retired slots were removed, zero remained, 2,143 source slots/4.03 MB input and 13.19 MB estimated temporary work were charged. Three alternating stress pairs had essentially unchanged compaction median (65.539 versus 65.369 ms). A subsequent flush retained durable revision 178, and the pinned revision still returned 5,000 records. Managed first flush median was 253.822 ms in seven fresh builds; a second unchanged flush returned in 0.001161 ms median. The 5,000-file mutation stress recorded incremental flushes, including 41.803 ms in one bounded-budget run. Separate 4,096/16,384/32,768-file locality fixtures measured verified-update medians 5.043/5.607/6.249 ms and p95 5.701/5.800/8.225 ms.

`cargo test --workspace --locked --quiet --jobs 2` passed at `471b79c35b`: 962 tests, 0 failures, 18 ignored across 23 test binaries. Focused codec, ordered dictionary, bigram, mutation/compaction, managed-store fault, and storage-reopen tests are included. The suite covers malformed descriptors/payloads, domain mismatch, failed streamed write and retry, failed flush retaining the older durable generation, truncated manifest, and pinned compaction. The CLI/TUI and desktop policy/status work was integrated before this follow-up; prior native GUI and process smoke results are in the existing hybrid task notes. The final implementation was not merged into `master`.
