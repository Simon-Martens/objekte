## Reproduction and limits

On the same Linux host: Rust/Cargo 1.99.1, system allocator, CPU affinity 0–31, performance governor, 32 build workers, one query worker, locked dependency digest `dc29ff42cf24b2cc4de67a2297f3c4d676c9034c0b91315465d1fb1136b486f7`, and unchanged 148,498-file Musenalm fixture. The manifest records content and metadata hashes and each binary hash. Commands were `cargo fmt --all -- --check`, `cargo check --workspace --all-targets`, `cargo test --workspace`, the ignored descriptor stress test, release build of the five benchmark examples, then `run_candidate.py`, `run_after_only.py`, `run_confirmations.py`, and `summarize.py` with the frozen base and final binaries. All checks passed. Candidate runs at `f0e600458d`, `34d17b7b82`, `4de52f87d2`, and `7ce3f6e525` are retained to show the fixes to earlier material memory and drain regressions.

The preexisting supported durable modes do not serialize the transient direct-link session spool, so no durable migration is needed in this repair. The second authorized task deliberately changes the direct-link public contract; that work belongs on its separate child integration branch. File source revision still uses the original observed-revision contract in this repair. There is no observed correctness or material performance blocker for this revision.
