## Method

The benchmark was the existing release `bench_index_construction` example and [comparison driver](../../../bench/results/index-construction-optimization/2026-11-12-master-737cfb77/compare.py), extended only with `--append-pairs`. Both roles used `cargo build --release --locked -p objekte-search-core --example bench_index_construction`, separate target directories, fresh processes, one warm-up per role, alternating order, the same canonical root `/home/simon/source/objekte/examples/musenalm`, and profiling disabled during ordinary timing. Five pairs were predetermined for each candidate and alphabet at 32 workers. Four more were appended to the *same* B2 and C comparisons when their first five were inconclusive. Admission also used three pairs per alphabet at each of 1, 4, 8 and 16 workers. The final retained combination used five new pairs. No prior successful pair was replaced. The [protocol](../../../bench/results/index-construction-experiment-revision/2026-11-12-b54dcac5/README.md) and per-run manifests preserve exact commands, revisions and hashes. A failed final output-path preflight stopped before measured pairs and is excluded.

Corpus: 148,486 files and logical records, 193,297,230 source bytes; inventory fingerprint `9f93a4ba7fb9249c9c4eb04e03ed911435a6b0493f15b087a5447add32456aa9`, schema fingerprint `4115070eb30b0af98b109429d0883b493f857cdf671ec55b943d91b73c5ebfe3`. ## Structural and diagnostic findings

**A, storage.** The former rejected arena required linked traversal and per-block rebase/link updates. The retained implementation accumulates `(gram, local word position)` in a bounded worker-local table, groups/sorts once, and packs each gram's 64-record bitmap words into contiguous spans described by offsets/counts. A chunk retains one admitted global base and owns its packed allocation; only local positions are stored until conversion. Admission moves owned payload allocations into the global accumulator, separate from extraction-batch lifetime, without a block-by-block global rebase. This is not zero-copy: packing copied 108,918,016 ASCII / 115,969,584 Unicode block bytes in the full corpus. There were 302 retained chunks and 1,111,671 / 1,249,051 per-chunk spans. Empty columns stay sparse; scratch shrinks under a bound. Descriptor coverage, order, uniqueness, arithmetic and slot-boundary validation are retained and tested. Final conversion and destruction remain in full-build time.

The [16-worker opt-in capacity profile](../../../bench/results/index-construction-experiment-revision/2026-11-12-b54dcac5/storage-profile/README.md) reported final global element-capacity **lower bounds** of 175,316,640 → 129,252,704 bytes ASCII and 186,578,224 → 145,299,088 Unicode; ready contribution lower bounds were 18,558,336 → 14,037,136 and 21,256,832 → 15,744,512. Separate profiled process peak RSS was 515.9 → 453.4 MiB ASCII and 522.1 → 469.2 Unicode. These sampled capacities omit map control bytes, allocator rounding and active worker state; ready/global peaks are not simultaneous. The [focused 10,000-record debug DHAT fixture](../../../bench/results/index-construction-experiment-revision/2026-11-12-b54dcac5/allocations/README.md) showed fewer allocation blocks (71,545 → 71,116 ASCII; 71,963 → 71,380 Unicode), but *higher* gross allocated bytes (3,949,868 → 4,364,008; 4,375,046 → 4,665,634) and peak live bytes (2,507,547 → 2,670,823; 2,691,291 → 2,796,703). DHAT covers a debug test process/fixture and does not contradict lower full-corpus release capacity/RSS. The [detailed opt-in work counters](../../../bench/results/index-construction-experiment-revision/2026-11-12-b54dcac5/storage-profile/README.md) record 119.279/121.734 million gram lookups, 63.004/63.676 million duplicate-bit ORs, 6.807/7.248 million entries sorted, 17.776/21.731 ms summed packing service, and 151.676/154.697 ms final bigram conversion/destruction wall intervals (ASCII/Unicode). Service sums overlap across workers and cannot be read as CPU time or added to wall time.

**B, admission.** The former prototype offered only one posting task and one text task. B1 prepared disjoint posting-field and text-store destinations on the coordinator, used safe scoped borrows and one per-batch join, and preserved coordinator record/identity/slot ordering and deterministic error precedence. Its gate grouped only 9 of 293 batches, none in dominant `contents`; it was therefore an inadequate full-corpus test. B2 used separate coarse posting/text work thresholds, at most four groups, and inline handling when a class had no useful group. A realistic 37-field fixture, bounded-admission tests and a simultaneous-error test passed. In [opt-in profiles](../../../bench/results/index-construction-experiment-revision/2026-11-12-b54dcac5/admission-profile/README.md), B2 grouped all 262 `contents` batches (785 posting groups and 262 text groups), reaching four concurrent groups at 32 workers. Actual interval overlap was 251.906 ms ASCII / 240.262 Unicode over those batches. At four workers it achieved only 67.610 / 42.342 ms overlap while summed preparation/submission grew to 262.080 / 420.051 ms and submission-to-start delay to 712.826 / 772.011 ms. Separate profiled admission wall intervals were 598.88 → 878.16 ms ASCII and 557.12 → 1049.37 Unicode. Ready-to-admission delay, ordered record admission, preparation, submission-to-start, group execution, merge/join and remaining sequential work are separated in the raw profile. These are overlapping elapsed intervals and queue residence, not recoverable wall time or CPU usage. The ordinary matrix establishes the 4/16-worker regression; B2 is rejected despite modest 32-worker ASCII gain.

**C, SIMD.** The earlier rejected SIMD version folded bytes to a temporary buffer and then ran the scalar byte sink. The revised x86_64 AVX2 path forms adjacent and skip-one u16 gram keys and endpoint validity masks for eligible 32-byte ASCII blocks, including carry across chunks; scalar insertion/duplicate handling remains. The scalar path handles short/mixed tails and all Unicode-alphabet text, with runtime AVX2 dispatch, so the binary stays portable. Forced-backend differential tests cover all ASCII bytes, relevant alignments and lengths, mixed UTF-8/fold expansions, transition boundaries, emitted grams and final membership. [Focused checksum and real-builder measurements](../../../bench/results/index-construction-experiment-revision/2026-11-12-b54dcac5/simd/README.md) include 0–8, 16/32/64/128, 1–2 KiB, repeated/varied and non-ASCII segments. Real-builder examples: 32-byte ASCII 1.555 → 1.253 ms, 64-byte 1.127 → 0.819, 128-byte 0.896 → 0.587, varied 966-byte 2.489 → 1.491; predominantly non-ASCII 2176-byte 1.316 → 1.430. Focused timings include insertion and completion, but are not corpus-weighted. Nine-pair full builds found no repeatable two-alphabet benefit of sufficient size to justify the dispatch and unsafe-intrinsic complexity; reject C.

## Correctness and limits

At retained code `ceebc48811`, `cargo test --workspace --locked` passed **820 tests, 0 failed, 18 ignored** across 21 result groups. `cargo clippy --workspace --all-targets --locked` exited 0 with warnings also present at B. The spacing script and `cargo fmt --all -- --check` each fail on both clean B and candidate at the same unchanged `crates/cli/src/execution.rs` import ordering; [baseline and candidate logs](../../../bench/results/index-construction-experiment-revision/2026-11-12-b54dcac5/validation/README.md) are archived. `git diff --check B...HEAD` passed. Focused A, B and C tests also passed on their respective branches.

The [extended Musenalm verifier](../../../bench/results/index-construction-experiment-revision/2026-11-12-b54dcac5/query/README.md) compared all 194 `(count, ordered SearchHit list)` digests between fresh B and final builds: **194/194 match in each alphabet**, including identity, source ranges, status, diagnostics, matched fields and payload. Both parsed 148,486 records. [B and final snapshots](../../../bench/results/index-construction-experiment-revision/2026-11-12-b54dcac5/snapshot/README.md) have the same sizes per alphabet (129,139,458 ASCII; 131,650,034 Unicode bytes). All four restored under the candidate in required-load mode with `restored=true`, `build_parses=0`, and all 194 ordered query digests identical to fresh results. Snapshot byte hashes differ because serialization order is not the logical compatibility contract; exact hashes and manifests are archived. The large payloads remain in the integration worktree's ignored `target/index-construction-experiment-revision/snapshot-payloads/`, not Git.

Performance conclusions apply to this host, corpus, schema, compiler and worker matrix. The B selfcheck had both −36.082 and +8.128 ms deltas, illustrating normal timing noise; small candidate medians within their observed spread were treated conservatively. A's consistent two-alphabet wins and lower full-corpus memory justify retention. B/C remain available on pushed experiment branches for inspection, without adding their code to the integration result. No separate issue was required; the rejected experiments are documented here with raw evidence.
