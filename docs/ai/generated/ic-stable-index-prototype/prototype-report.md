## Decision

**Performance rejection.** The complete prototype functionality is implemented,
including direct construction from native batch contributions, standalone files,
lazy generations, mutation, failover, synthetic fixtures and the matched
campaign. Both construction latency and memory exceed the gates:

- Musenalm P=8 median: **4.959 s stable vs 1.699 s native**, **2.92x**.
- Resident RSS: **763 MB vs 398 MB**, **1.92x**.
- Peak RSS: **880 MB vs 411 MB**, **2.14x**.
- Synthetic P=8: **1.769 s vs 0.762 s**, **2.32x**; resident **2.05x**, peak
  **2.29x**.

The stable component construction stage alone was 3.179 s at P=8, 1.87x the
entire native build. No production migration or master merge is implied.

## Implemented functionality

Feature `ic-stable-prototype` with optional `ic-stable-structures = "=0.7.2"`.

- One owned `RefCell<Vec<u8>>` and one B-tree per component.
- Independent physical-file, path, record, identity and domain catalogs.
- Typed, length, state, normal/skip gram, sort and relation components.
- Self-contained 128-byte envelope, embedded descriptor, descriptor/payload
  SHA-256, entry count, pinned crate/layout identity and V2 layout rejection.
- Standalone `save_index`, `open_index`, `save_as`, raw range/insert/remove and
  checked component-key kinds.
- Snapshot manifest, lazy loading with `BTreeMap::load`, unchanged-unloaded
  stream copy, bounded parallel component publication (`min(4, cores)`),
  staging/rename publication and directory sync.
- Known-key mutation, posting batches, append/delete/replace/move lifecycle.
- Direct source build: discovery, bounded extraction, native contribution
  accumulation, native-independent finalization and parallel stable component
  construction. No production `Repository` is built by the benchmark path.
- Deterministic component descriptor sorting and stable numeric IDs.
- Descriptor dependency identities and explicit `Failed` component state.
- Build-time component start/end/worker trace and overlap evidence.

## Required fixtures and correctness

35 focused tests cover:

- empty repository, multiple collections sharing one path, multi-record files,
  duplicate logical identities, non-UTF-8 Unix paths;
- exact large/negative/decimal numbers, nulls, absent fields, empty arrays,
  structural states and custom bindings;
- raw-fallback malformed JSONL and diagnostics;
- Unicode alphabets and text;
- equal sort keys and native record-ID tie-breaking;
- resolved/dangling relations, occurrence multiplicity and target postings;
- standalone save/copy/rename/open/mutate/save-as without a manifest;
- lazy generations, all-component load with zero insertion calls, second
  generation, old-generation survival, source-free catalog/query access;
- unchanged-unloaded component copy without loading;
- first field query loading only its dictionary and live domain;
- known-key mutation after reopen and second save;
- corruption, missing member, malformed manifest, swapped component, wrong
  component identity and wrong key kind;
- injected failures before/after component open, payload write, sync, manifest
  write, staging sync and rename, including RAM restoration and retry;
- P=1/P=2/P=4 descriptor and semantic determinism;
- direct source build validated against native repository semantics.

Full Musenalm direct-build validation passed with zero errors:
148,486 files/records, 152,544 posting keys, 2,814,411 posting memberships,
25,477 gram keys, 56,275,908 gram memberships and 566,768 sort entries.

## Persistence, primitives and mutation

- Snapshot save: **0.326 s** for 1,323 components / ~409 MB with bounded
  parallel component I/O.
- Manifest open without payloads: **27 ms**.
- First load of a 27.9 MB typed component: **26.7 ms**.
- Standalone open: about 28 ms; standalone re-save: about 66 ms.
- Resident exact posting lookups: 0.005-0.161 ms.
- 65,536-member standalone mutation: 36.2 ms; save 35.9 ms; reopen succeeded
  with one added key and `detached=true`.
- Lifecycle: ten replacements of a 200-record file produced 2,000 dead slots
  (2,200 high water / 200 live). Reopened payload grew from 1.18 MB to 1.57 MB
  (33%), snapshot disk usage 1.76 MB. Logical deletion does not reclaim posting
  memberships.

## Remaining limitations

1. Configured composite sorts are still rejected explicitly. The selected
   Musenalm and synthetic profiles contain none.
2. Memory exceeds the gate because native accumulators remain alive while stable
   images are constructed. Streaming per-family ownership transfer would be the
   next design experiment.
3. File deletion is logical; dead slots and old posting bytes remain until a
   future compaction design.
4. Mutation and snapshots require exclusive prototype access; no live MVCC.
5. Only Linux was executed. macOS/Windows host coverage was unavailable; path
   keys are platform tagged.
6. FTS primitives return candidate sets; the benchmark does not claim a full
   verified FTS adapter or general Repository API parity.
