## Review verdict

**Blocked on logical defects and demonstrated inefficiencies.** The branch delivers retained and versioned-provider ingestion, optional provenance, ordered receipts, overflow and lookup routes. Compaction and retirement can lose live records or their routes. Mixed-source planning can exclude true matches. Publishing a new index root for each queued singleton and scanning unrelated segments for a local change are outstanding implementation defects.

**Release decision.** The observed +490 µs add and +11 µs move differences are accepted as timing observations. The original 10% / 5 µs per-operation rule is retired for this repair. All logical errors and verified unnecessary work remain mandatory fixes, even when a single occurrence costs only microseconds. For example, an index-wide route rebuild on one file change fails the locality requirement even if the current fixture completes quickly. ## R1 · Preserve every live record through physical compaction — first repair

**Failure.** In `crates/core/src/lifecycle/maintenance/compaction/partition.rs:57–125`, partition selection visits `source.files` and seals only when its file set is nonempty. A live unlinked slot is never selected. A partially retired fileless segment produces no parts. Explicit compaction replaces the old segment group with these parts in `compaction/mod.rs:194–254`; it publishes without checking conservation of the live population. The automatic retirement path calls the same partitioner in `lifecycle/publication.rs:575–615`. Even when an independent record has a link, `index/segment/compaction.rs:174–185,243–255,388` requires a file locator and constructs a `FileRange` output. A retained value or versioned provider can thereby lose its authoritative backing.

**Reproduce first.** Insert unlinked retained A and B in the **same batch and segment**. Pin V1, delete B in another batch, await its receipt, then call `compact()`. The current view must still return A’s original logical value, exactly one live ID, and `OriginalBytesUnavailable` for A’s bytes. V1 must still return both records. The existing `routed_direct_lookup_survives_many_batches_and_compaction` test checks the replacement key after compaction. In this regression the essential assertion is the *untouched survivor in the partially retired segment*.

**Implement.** Feed all backing variants through the existing slot-remap and index-family projection machinery. Select native partitions from the active-slot domain. Use optional links for file limits and reverse membership only. Preserve file-adapter handling of valid empty files and diagnostics. Project retained block addresses, share referenced immutable blocks, release wholly unreferenced blocks, and project provider versions and registration identity. Keep the backing variant through compaction and consolidation. Project optional range and path-only links independently. Rebuild or patch the affected routes in the same root as the masks. Verify that each input live slot is mapped exactly once and that the output live count equals the input live count for the touched partition. An invalid candidate must never be installed.

**Acceptance.** Repeat with a provider and with linked, path-only and unlinked records in a single native segment. Store bytes different from the retained value in the provenance file, and check byte authority after compaction. Check full key membership, logical payload, provider version, forward/reverse links, sort order, indexed count and pinned views. Exercise automatic compaction with a segment of at least 256 records and at least one quarter retired, then trigger admission. Verify survivor identities, including records outside the changed set.

## R2 · Use physical ownership for retirement and file lifecycle

**A live route can be deleted by an obsolete file incarnation.** `lifecycle/publication.rs:697–720` counts the slots that are still live, then removes the ID route of *every* historical slot associated with the file. Removal is by ID alone. Example with intrinsic IDs and small delta segments: add file A with key K, append-replace A with J, add file B with K, then delete A. A’s obsolete K can remove B’s live route. Enumeration and direct lookup can disagree, and a later strict insert can miss a duplicate. Exercise this before physical removal of the old incarnation.

Retire only previously active addresses owned by the file importer. Remove a route only when its current segment ID and slot equal the address being retired. Walk participating segments using the reverse routes. Check the entire sequence with direct lookup, exact count, duplicate insertion, file-to-record and record-to-file lookup, and a view pinned while B owns K.

**Catalog association does not identify an importer.** `lifecycle/mutation/mod.rs:371–384` classifies a file by asking whether *any associated collection has a file source*. A registrar in a mixed collection may declare `attachments/cover.bin` while that collection imports only `data/*.json`. Updating or moving the attachment can go through file preparation and fail with “no configured collection selects this file”. Keep importer membership distinct from independent links, including an importer-owned empty file. Preserve path-only links through content replacement and clear obsolete range links. Linkless retained/provider records remain live after file deletion. Handle a file shared across multiple collections. For a move, evaluate destination selection under the existing file-adapter rules; a change of importer membership must take the appropriate reindexing path.

**Limit the publication work.** `refresh_record_links` at `lifecycle/publication.rs:730–791` makes each collection’s segment vector mutable, can clone an entire indexed segment to change its links, and reconstructs every route in a changed collection. Use participating file routes, update only affected link tables and reverse entries, and share unchanged postings, sort columns and bodies. A metadata-only change must update whichever stored metadata sort keys depend on it (R4). Exercise updates with many unrelated segments and confirm localized work. An unchanged path/metadata association should avoid catalog or route reconstruction where possible.

## R3 · Make optional file services safe in normal public operations

**Fileless calls and mixed reconciliation.** `inventory/mod.rs:797` implements `required_root()` with `expect`. Public `add_file` reaches it through `mutation/preparation.rs:200–207`. Absolute `file_handle_for_path` reaches it at `lifecycle/view.rs:535–538`. Reconciliation at `lifecycle/reconciliation/mod.rs:122–128` requires a root and unconditionally requests a file definition for *every* collection. The worker catches the resulting panic and reports a generic failure. Check capability at public boundaries. Return the existing appropriate error or absence for file-only operations. Reconcile actual file-import registrations with their **original CollectionId**. The scanner at `reconciliation/scan/mod.rs:103–110` currently assigns IDs by enumerating its input. Simply filtering the definition vector renumbers mixed collections. Compare discovery memberships with importer memberships during reconciliation and preserve independently declared files.

**Rebuild visits obsolete incarnations.** The programmatic arm in `lifecycle/maintenance/rebuild.rs:48–146` checks every stored file row, including those whose slots were retired, then republishes the old root. An append-replaced or deleted file can produce an obsolete-revision or unknown-file error after the explicit mutation has already succeeded. Implement rebuild by ownership. Rebuild configured file input according to the original file lifecycle, retain independent values/links and registration handles, and check live provider tokens on authoritative reread. Retain the old root on a real read, validation or publication failure. A deliberately stale provider must still fail. Distinguish the original spec’s checked file-version semantics from the benign case of an obsolete slot that nobody needs to read.

**Acceptance.** Cover an index with no catalog, an explicitly empty catalog, and a typed-only collection at ordinal 0 followed by a file importer at ordinal 1. Run public reconciliation on a changed file and an unchanged pass. Verify IDs, reverse memberships, revision behavior, and the report. Rebuild after successful append replacement and deletion, including retained/provider records beside the importer. Preserve a pinned view. Include valid empty imported files and a declared file outside the importer’s selection. Fileless requests must complete without a process or worker panic.

## R4 · Make text coverage, sorting, payload access and reuse backing-aware

1. **Candidate completeness.** `query_execution/restrictions.rs:872–902,1304–1312` allows a raw bigram index to restrict a structured field predicate from the collection file reader’s coverage declaration. `construction/batch.rs:828–852` can populate a typed segment’s raw index from explicitly supplied adapter text. In a collection with a JSON importer, submit a native record with logical `note = "Leipzig"` and a nonempty adapter text segment containing only `"Dresden"`. An unindexed logical `note ~ 'Leipzig'` must retain that record even if the raw grams omit Leipzig. Run with enough decoys to exercise the planner’s raw-index offer. Include the converse unscoped FTS case where the adapter representation is authoritative. Carry the actual representation and conservative coverage at segment/registration level, including batches mixing explicit and derived text. Use an unrestricted residual when field coverage is incomplete. Prove the result against explicit expected IDs.
2. **Metadata sort keys.** Typed admission passes `None, None` for file and root at `construction/batch.rs:852`. `SortBuilder::add` writes a stored key from those inputs (`index/sorting/mod.rs:329–345`); `ingestion/publication.rs:320` attaches links after finalization. A declared `@file.path` or range sort can therefore contain missing keys for linked records. Supply validated origin/root when generating the keys, or resolve mutable catalog-derived keys against the pinned view through a correct ordered path. Cover mixed origins, path-only links, moves, replacements and deleted links. Use IDs deliberately in reverse path order, check both directions and deep pages, and assert the exact expected IDs.
3. **Source accounting and limits.** In `query_execution/runner/mod.rs:3433–3507` every selected logical payload can be charged as a source read/parse, and the origin range supplies its byte charge. A retained value can be refused under a source-read limit even though it requires no I/O. Dispatch authorization, work counters and source diagnostics by backing. Retained logical reads borrow or materialize memory, provider reads charge the actual provider operation, and file-range reads charge checked file access. A link alone authorizes neither an original-byte fetch nor a file-read charge. Test a retained winner with zero source-read allowance and a linked retained winner with a large range. Verify actual reader calls and file counters for all three backings.
4. **Verified reuse and relation cost.** `runner/mod.rs:2289–2304,4030–4042` uses the presence of a single native segment anywhere in the repository to disable the verified-cache path and ordered cursor, even for an unrelated file collection. Scope eligibility to participating collections/dependencies. Support native addresses in verified reuse as the spec requires, with publication and representation identity, version-checked payload rereads, and correct stale-provider handling. Check a repeated eligible query with cache enabled against cache disabled, with observed reuse, then mutate. Correct output on a permanently bypassed cache does not exercise reuse.
5. **Avoid rebuilding query results as intermediates.** `runner/relations.rs:2164,2377–2422,2573–2594` constructs string-keyed truth/address maps for the active domain and runs leaf queries with a full-universe result limit. `query_execution/relations/view.rs:364–419` clones retained values and text or requests a full provider value for a residual. Use existing per-segment set/proof interfaces and bounded winner selection for optimized Boolean branches. Borrow immutable retained bodies, request the necessary provider fields/text and batch compatible reads. Use one source-neutral residual/reference path for unsupported cases. Preserve three-valued relation semantics, cancellation and work limits. Check a selective count and a deep page over mixed sources, with a dangling target and a provider that logs its projections. Measure intermediate records or allocations. Keep broad query-engine reorganization outside this repair.

## R5 · Enforce batch identity, ordering and resource limits

- **Batch-local file tokens.** `ingestion/mod.rs:22,168–209` represents a token as a vector index. If batches A and B both declare their first file, B accepts A’s token and binds to B’s file. Carry an opaque batch identity in the public token and validate it before adding a link. Serialize checked local indices in the private frame. Test same-session same-ordinal tokens and different sessions. A refused/retried batch retains its valid tokens.
- **Reader capability at input construction.** `insert_from_reader*` and `replace_from_reader` accept a plain retained writer; the missing reader is discovered in `install_batch` after acceptance and fails the session suffix. Capture the registered access capability in the writer/batch or use a checked provider input constructor. Check optional link capability at the public input boundary. Allow authoritative value, supplied text, optional link and provider token in the supported insert/replace combinations without a combinatorial set of methods. Keep commit-time revalidation. A caller’s use of the wrong capability must leave later valid work usable.
- **Session termination and publication.** `ingestion/queue.rs:179–186,267–295` closes admission before the previous worker necessarily finishes. The index tracks a weak session and opens a successor as soon as `is_open()` becomes false (`lifecycle/builder.rs:104–136`). Last-owner drop can also make the weak handle expire during drain. Separately, the worker’s final cancellation check at `ingestion/publication.rs:230` precedes the publication write lock and root swap. Give the worker/coordinator a draining-state lifetime until the old accepted prefix is terminal. Serialize cancellation with the publication decision, preserving batches already installed. Use deterministic barriers to hold an old worker immediately before installation, drop all public owners or call finish/cancel, and request a successor. Prove ordered, exactly-once publication, correct terminal receipts, successful prefix and cancelled suffix. Never wait for drains while holding the root write lock.
- **Memory estimation and spool reservations.** `ingestion/mod.rs:344–369` counts string lengths and visited values, omits unused vector/string capacity and exact-decimal digit storage. An empty string with a large capacity can pass a tiny batch limit. Account owned capacity with saturating arithmetic when forming the batch, including text paths, nested arrays and decimal digits. `queue.rs:358–386` encodes before reserving disk bytes, even with a zero spool budget, and `spool.rs:36–47` keeps a payload and a second complete frame during the copy. Short-circuit memory-only refusal. Bound concurrent encoding/staging, reserve first or stream with a bounded reservation, and account for space held by partially consumed chunks until reclaimed. Preserve checked lengths, checksums, rollback and caller ownership.
- **Descriptor overflow.** `queue.rs:340–342,371–375,407–415` makes 65,536 waiting descriptors a hard limit on submissions, including disk-backed frames. The original §5 requires bounded resident descriptors **and** sequential overflow bookkeeping. Keep the descriptor cap, support further ordinary submissions within available spool quota, and return `WouldBlock` for a transient memory-only offer. Use compact sequence/chunk bookkeeping with shared receipt completion for a prefix. Validate a paused worker with more than 65,536 tiny submissions, a dropped receipt, spill disabled, injected partial write and close during a reservation. Check cleanup and exactly-once results without holding the admission lock during disk I/O.

## R6 · Group accepted batches for segment construction

The worker at `ingestion/queue.rs:452–519` dequeues exactly one item for each call to `install_batch`. That call partitions only the records in that batch, constructs indexes, and publishes a root. The measured 65,536 singleton submissions therefore pay for 65,536 constructions and installations. The reported final 64 segments have already undergone sparse consolidation. Four producer threads do not parallelize this preparation stage. This is an implementation mismatch even though the absolute-cost benchmark has no numeric throughput gate.

Drain a bounded prefix of already available submissions. Prepare compatible records by collection, registration, representation and backing using the existing construction and bounded segment-job machinery. Honor `SegmentPolicy` record and distinct-file limits. Stage operations in ordinal order, including multiple operations on the same key in different batches. Keep each batch atomic across its segments. Coalesce compatible completed batches into a root and return that revision to every covered receipt. Retain enough batch-boundary information to install the valid prefix when a middle batch fails. A group-wide rollback of preceding valid batches violates the receipt contract. Seal promptly on idle, flush and finish. Bound input bytes, jobs and completed work waiting for an earlier sequence.

Construct provider-backed columns directly. Currently `build_segment` first allocates retained blocks, addresses and links, finalizes and computes accounting, then replaces the backing with provider versions, attaches links and computes accounting again (`ingestion/publication.rs:290–322`, `construction/segment_admission.rs:799–850,1088`). Move decoded values through logical indexing once and release them when no longer needed. Keep shared retained blocks only for retained input.

**Acceptance.** Queue a deterministic backlog of compatible singletons while the worker is paused. After release, demonstrate that one initial segment contains records from several submitted batches and one installation completes several receipts. Record initial seals, consolidations and root installations as the backlog grows. Explain each boundary using the segment policy, work budget, idle drain, barrier or failure. Verify complete membership, bounded work and correct prefix publication. Include a batch exceeding the segment target, repeated changes to one ID, one idle submission and a flush followed by later submissions. Repeat the original 1/256-record and 1/4-producer runs and report records/s, resident/in-flight high water, acceptance and drain time against the reviewed 30.367 s and 176.768 ms. An unexplained seconds-scale drain at 65,536 records warrants profiling through resolution.
