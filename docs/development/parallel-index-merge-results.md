# Parallel index merge follow-up

Branch: `fix/parallel-index-construction`. This continuation began at `ebff8c306f823ed6534bdd41cda0f59fde531d5c` and kept the existing working tree and history. The implementation is committed and pushed in three independently reviewable steps:

| Commit | Change |
| --- | --- |
| `da87b92c647709b1203ce4f6e9ab2fc06f834515` | Separate ordered record/diagnostic admission from index merging; retain serial merge behavior. |
| `84a746941b94b2afbb4624500463914efc491885` | Move compatible base-zero posting and bigram stores, typed bitmaps and initial sort-key vectors into empty destinations. Nonzero bases retain checked slot translation. |
| `6ac1de4f2834e1d368e8dd545dba071d65d9e2bf` | Merge disjoint destinations on the existing construction pool, with a barrier before the next batch. This is the independently revertible parallel-execution commit. |

The coordinator still admits record identities, file mappings, byte ranges, diagnostic references and status in order. It also appends logical-record membership and sort-key vectors serially. Within one batch, ordinary posting fields, custom posting bindings, raw and fallback bigram indexes, and custom text indexes merge as separate jobs. Jobs own their incoming maps and bitmaps and borrow exclusive mutable destinations; they do not clone contributions. Empty or single-destination batches use the serial path, and all jobs finish before the next batch can merge. Representation, coverage and key-set checks run before job launch. Multiple job errors are inspected in stable destination order. No source record is reparsed and no snapshot representation changed.

The parallel path leaves one large field or gram store internally serial. It shares the existing worker budget with source processing and does not introduce a new pool, detached merge jobs, or an index mutex. A base-zero destination can adopt an entire compatible local posting/bigram index; a sort column can adopt its first key vector. These are structural allocation changes, not measured allocation savings.
