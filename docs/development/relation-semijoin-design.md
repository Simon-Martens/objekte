# Relation semijoin proof scope

TASK-07 starts after the independently checked TASK-06 evaluator is integrated. The planner restricts positive, source-independent forward relation terms when an exact true target is a valid source witness. Target gram candidates remain approximate until terminal verification. A source reached through a verified target and the declared reverse posting is an exact positive witness and may supply evidence; unrelated predicates remain residual. No approximate or complemented relation membership is treated as exact.

The planner compares two bounded alternatives against the current source domain. Target-first verifies distinct terminal targets using their indexes and grouped reads, then maps confirmed target IDs through the existing reverse posting. Source-restricted walks only the already filtered source slots, deduplicates reachable targets, verifies each once, and retains sources with a true witness. The choice includes target candidate work, source and target fan-out, reverse membership, and file work. Each semijoin term deduplicates target verification within its own execution. Separate predicates can still read the same target separately; source-dependent right operands retain scanner evaluation.

Apply this restriction only to a root positive term or an AND member whose own truth is necessary for the whole expression. `ANY` is eligible; the default quantifier is eligible only when every forward hop is declared scalar and no array ancestor or position intervenes. OR and NOT need their full three-valued domains. Universal/default array truth, positional selectors, backlinks, source-dependent comparisons, and unresolved target states remain scanner residuals. In particular, an empty array can satisfy a universal predicate; `?!= 'A'` is true for `[A, B]`; two existential AND terms can use different target witnesses; and an unpositioned reverse posting cannot prove an indexed array occurrence.

Selected relation FTS can use the same witness path when every selected field is an unpositioned forward relation field. It verifies literal or regex matches on distinct targets, then records each matching source's original selected-field evidence. Mixed local/relation fields and backlinks retain scanner verification. The current selected FTS field type cannot express an explicit array position; that remains separate cross-feature work.

EXPLAIN identifies the chosen strategy, estimates, observed candidates, target reads, source residuals and relation work counters. Target sets and edge visits have explicit limits; target reads are grouped into bounded batches. Forced-strategy and seeded fixtures cover candidate membership, selected literal/regex FTS, shared targets, dangling and unavailable targets, mixed fallback records, high-fan-out arrays and multi-hop paths. A target shared by many source edges is decoded once within one semijoin term.
