# Declared relation indexing

`Schema::register_relation(RelationDefinition)` declares a source field path, target collection, `One`/`Many` cardinality and optional reverse alias. The field must already be registered as `Id` or `Array<Id>`, and the cardinality must agree with its array/multi declaration. Registration makes the typed value posting mandatory even when the field was not otherwise indexed. Collection names and reverse-alias uniqueness are checked before source discovery. Declarations are ordered by path and receive `RelationId { source, ordinal }` in collection-definition order.

Workers extract reference occurrences while building normal postings and grams from the same parsed logical record. Each occurrence retains its nested array-index path, from outermost to innermost. Ordered admission translates local source slots once. After all collection ID lookups exist, each relation becomes an immutable CSR array: one offset per source record plus resolved target slots or unresolved ID text. Repeated occurrences remain in the forward array; the existing typed posting deduplicates source membership for reverse traversal. Unresolved IDs are retained without changing parser status. The source's file ID remains in `CollectionGeneration`, so an edge does not duplicate provenance.

The read-only API is `Repository::relation_index(source_collection, path)`, `Repository::backlink_relation(target_collection, alias)` and `Repository::relation_reverse_sources(relation, target_id)`. `RelationIndex::edges(source_slot)` returns occurrences; `unresolved_references()` reports dangling source slots, ID text and positions without modifying parser status. Its `present`, `nulls`, `empty_arrays` and `unavailable` bitmaps distinguish missing, explicit null, empty arrays and raw fallback records. Null/empty occurrence positions are intentionally not in the compact adjacency; a later positional evaluator must verify those cases from the source record. A dangling edge is `RelationTarget::Unresolved`, distinct from all of those states. The relation index does not implement query traversal or semijoin planning yet.

The snapshot carries the immutable adjacency. Restore validates declaration identity, source/target slot bounds, fallback availability, resolved target namespace, unresolved IDs and forward/reverse membership against the typed posting dictionary. The schema fingerprint includes all relation declarations. This layout advances `MODEL_VERSION` from 6 to 7 and `SNAPSHOT_VERSION` from 7 to 8; older snapshots rebuild through the existing compatibility path. Collections without declarations retain empty relation vectors and do not allocate per-record graph entries.

The focused fixture builds eight healthy records and one malformed source once. Its two-level arrays retain every source occurrence path, and nested empty arrays keep the same presence as the typed posting. Fresh and restored repositories pass the same checks. The two target IDs in one JSONL file and healthy/malformed JSONL siblings retain correct slots and file ownership. Small-fixture CSR heap estimates are under 4 KiB per relation; this is structural evidence, not a Musenalm memory or performance measurement. No new query benchmark was run for this work package.
