## Defects, fixes and focused regressions

1. **Native slot translation after compaction.** On the starting source, the public [downstream regression](../../../../extension-tests/src/review_findings.test.rs) added a native record before existing IDs, refreshed, initialized the native-to-selected translation, then called `save_bigram_cache` to compact native slots. Its uncached selective query lost a known match: total 1 instead of 2. The [failing output](baseline-regressions.log) records this. `FilePicker` now owns a process-local layout token. Insertions, deletions, compacting rebuilds and replacement pickers change the token. A selected snapshot reuses its translation only when its own source generation and the picker's exact token match. Failed translation stays a scan fallback and is retried after a new layout. The test now passes through save, deletion, explicit reindex and reopen. A [narrow picker test](../../../../core/src/file_picker/test.rs) verifies that the actual slot positions and token change. No token is persisted; snapshots continue to validate source and semantic identities.
2. **Scalar-cardinality errors.** The selected planner had used the native helper that exempts top-level scalar paths because the native picker has a separate array-risk summary. Selected postings lack that independent proof. The starting public regression returned a successful result for `year = 1848` while another custom record had `year: [1850,1851]`; direct evaluation raised “multiple values.” The same [failing output](baseline-regressions.log) records it. Selected candidate pruning now requires a safety proof for every scalar path in the bound filter, including top-level and unindexed residual paths. The native picker retains its own efficient array-risk check. Unknown selected safety leaves the affected records for exact evaluation; custom slots are never inferred safe from a native posting. [Tests](../../../../extension-tests/src/review_cardinality.test.rs) cover indexed and unindexed arrays, nested paths, filtered text nonmatches, later collections and pages, cache modes, scalar-to-array refresh, save/reopen, and legitimate existential, iteration, length and presence operations. An entirely scalar fixture still reads fewer than 10 of 66 sources for a rare term.
3. **Native indexes in mixed scopes.** Before the fix, the all-field rare text downstream regression visited 193 candidates and read 196 records because the selected route declined native text candidates; see the [failing output](mixed-pre-fix.log). The selected orchestrator now asks the existing native picker for compatible all-field, field and safe regex candidates, and translates native slots through the layout-bound map. Bound JSON `:fts` plans can likewise use native full-text candidates and combine them with typed/presence conditions. Custom slots remain a conservative exact-verification domain unless a compatible selected posting covers them. The bounded broad-posting heuristic retains a scan when mapping an index would cost more. Query-plan entries distinguish native text, native full-text, native scalar, selected posting and scan decisions; full-text is reported only when its candidate bits actually participated. [Mixed-source tests](../../../../extension-tests/src/review_mixed_indexes.test.rs) compare complete IDs, collection identities, totals, truncation and order with a separate direct repository. Rare all-field text, safe regex literals and JSON `:fts` visit fewer than 12 candidates across 193 selected records, including a native-only collection and a mixed collection. An unconstrained regex explicitly scans, multi-field requests preserve uncovered fields, OR fallback is complete, and markup-normalized custom text does not use incompatible JSON raw bigrams. A combined test checks text and JSON candidates after compaction, save and reopen. Sorted cached page changes cross partitions and read only the three returned records with no candidate regeneration.

The binding remains per collection. A native picker posting covers only its native slot partition, while a selected representation or scalar posting covers the sources for which its bound semantics apply. The shared selected inventory supplies stable source order and global pagination. Candidate enumeration does not reorder exact predicate evaluation, so fallible operators and cardinality checks retain their observable errors. A completed ordered-cache hit slices its generation-bound slots and materializes only the requested page.

## Remaining local fallbacks

A regex without a safe necessary literal, an index whose representation does not match the exact scanner, an unsupported or uncovered OR branch, a broad posting rejected by the bounded heuristic, or a partition with unknown scalar-cardinality safety can require exact scanning of its affected domain. Custom records are never pruned by native-only postings. Native `MetadataOnRequest` and `HashOnRequest` validation still perform their documented freshness work. The change does not add a general cost optimizer or new storage format. Native JSON snapshot bytes are unchanged, and the layout token exists only within a process; restored pickers receive a fresh token and rebuild their translation on first use.
