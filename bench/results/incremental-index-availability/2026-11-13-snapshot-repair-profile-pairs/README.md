# Plan 1 snapshot repair: paired profile campaign

Seven alternating pairs, with `before, after` on odd pairs and `after, before` on even pairs. Each mode in each pair ran three separate fresh processes: incremental construction without saving, incremental construction followed by `Index::flush_cache_with_stats`, and `Index::load_cache` from that mode's newly written snapshot. Every build used the Musenalm extended definitions, ASCII bigrams, 32 workers, `--profile`, and `--check-queries`. Byte attribution was disabled. The restore query checks ran only after load timing and memory capture. The original master is a separate nonincremental reference, not part of these pairs.

The before core is `bf39483f7c95368f222c760de04bde217b3dbe9d` (the reviewed Plan 1 implementation plus opt-in diagnostics). The after core is `2cb74685e113e12dd6b5f34bc36f57781e4ea2d8`. The same benchmark-only full-save-call and fresh-restore instrumentation was copied into the detached before worktree; its manifest records that dirty benchmark file. Both binaries were built with rustc 1.99.1, release profile. Corpus fingerprint: `9f93a4ba7fb9249c9c4eb04e03ed911435a6b0493f15b087a5447add32456aa9`.

`runs.json` contains all 42 command lines, manifests, raw samples, snapshot hashes, and trial order. `summary.json` gives medians, inclusive quartiles, ranges, raw values, and paired differences. Each snapshot was deleted after its restore sample to avoid retaining gigabytes of redundant binary artifacts; its size and SHA-256 remain recorded. Timings are nanoseconds, memory and snapshot sizes are bytes. RSS high-water marks are process cumulative, never reset between phases. The save call starts before lifecycle-state capture and ends after durable publication. The inner `SnapshotSaveStats.total_ns` starts later and is shown separately.

A second campaign without `--profile` is archived at `../2026-11-13-snapshot-repair-pairs/`. Both show the same direction of change. `../2026-11-13-snapshot-repair-pairs/byte_attribution.json` is an opt-in one-trial byte breakdown and must not be used as a timing or RSS trial. `../2026-11-13-snapshot-repair-pairs/unicode.json` contains a Unicode save/restore correctness and size check. `../2026-11-13-snapshot-repair-pairs/master_reference.json` is one fresh original-master nonincremental build/save reference; historical seven-run master medians are in the previous Plan 1 report.
