# Cumulative Plan 3 snapshot repair validation

Seven alternating paired trials compared the reviewed cumulative Plan 3 commit `7a9dee532e75bf167b6e4eabfd52277c79bb4df1` with its repaired merge `23d38d5e3fe5559879fc26a0e8bf0a803f2e51bb`. Each mode in each pair used separate fresh processes for construction, build plus explicit snapshot save, and snapshot restore. Musenalm extended definitions, ASCII bigrams, 32 workers, release rustc 1.99.1, `--profile`, and `--check-queries` were identical. Before and after used the same benchmark-only save-call/restore instrumentation; the before worktree has no core changes. `runs.json` records each command, manifest, sample, and snapshot hash. `summary.json` records raw values, medians, inclusive quartiles, and paired differences. Saved snapshot binaries were deleted after their own restore runs to bound archive size.

`byte_attribution_sample.json` is one opt-in repaired diagnostic with exact byte reconciliation; its timing and RSS are not part of the paired campaign. `full_query_before/` and `full_query_after/` contain full 220-case, four-profile query campaigns (880 rows), three repetitions per row, ASCII/Unicode and cache off/warm. `query_comparison.json` compares status, counts, normalized digests, and source-work counters and lists one-off latency outliers. `focused_queries/` contains three alternating seven-repetition pairs for the four outliers. `q214_isolated/` contains five alternating 15-repetition pairs for the one focused outlier still crossing both 10% and 0.5 ms; it did not repeat in isolation. The `verify_structural_reference` example also passed before and after for Q115–Q118 and Q120 with zero opens/parses/scans.

`SnapshotSaveStats.total_ns` is an inner writer timer that begins after lifecycle state capture and segment encoding. `snapshot_result.save_call_ns` is the complete external call and is the persistence latency metric. RSS high-water marks are process cumulative and never reset between phases. Query campaign snapshots are static repository snapshots and should not be conflated with the paired lifecycle snapshot sizes.
