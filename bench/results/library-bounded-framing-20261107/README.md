# Bounded JSONL construction experiment

## Measured revisions and method

- Baseline: `da0edfb21392be6495eb354bd70328f7fffff5d8` (detached worktree, whole-buffer oversized framing).
- Changed code: `4043acc23d` (bounded built-in JSONL framing and corrected admitted-weight counter; documentation-only ancestor `23c83af42f`). Both revisions were built with `cargo build --release -p objekte-search-core --lib`, Rust `1.99.1 (58cf8f9c3 2026-10-13)`, default release profile and no `RUSTFLAGS`, `CARGO_TARGET_DIR`, release-profile or Rayon environment overrides. The same external [`bench.rs`](bench.rs) was compiled with `rustc --edition=2024 -C opt-level=3`, linking each revision's release library. Baseline binary SHA-256: `a676758e12f2d6fc117ffeae4f8e65fa64ea505d581cbbbb5414e46df9de6c12`; changed binary: `fa75ef2a7b7ba5f3f735edb8895878a0cc22c49d1a28c3e3209e1ef293325d57`.
- Fixture: one generated `large.jsonl` in the R2 task worktree's ignored `target/r2-benchmark-fixture/data/`. It contains 8,192 JSONL records, each with an `id` and a repeated 12 KiB `text` string. Exact file size: 100,900,864 bytes; SHA-256: `7101d711f81a669517b9f4dd800bc283269b6cda921babdc139aa65cc07677e3`. The same absolute file and modification time were used for every process. The fixture can be regenerated by writing, for `number in range(8192)`, `{"id":"item-{number:04}","text":"` + 12,288 ASCII `x` bytes + `"}\n`.
- Configuration: ASCII bigrams, schema-free JSONL collection, generated IDs, snapshots disabled, four build workers, inference disabled by default, no source or decoded-result cache used by this build. The measured `wall_ns` encloses only `Repository::open_with_options`; signature generation occurs after timing. `/proc/self/status` RSS readings also occur before signature generation. Build stages come from `Repository::startup()`.
- Machine: Linux `7.2.13-200.fc44.x86_64`, x86_64, 13th Gen Intel Core i9-13900K, 32 available CPUs. Six fresh processes ran sequentially in one exclusive timing window, in `before/after`, `after/before`, `before/after` order. No cache dropping or timed warm-up loop was performed. The fixture and binaries were already compiled/generated before timing; ordinary filesystem cache and CPU frequency variation remain possible.
- Invocation for each binary: `BINARY /home/simon/source/objekte-library-bounded-framing-20261107/target/r2-benchmark-fixture`, with stdout saved as `before-N.json` or `after-N.json` and stderr as the matching `.stderr`. All processes exited successfully; all stderr files are empty. The harness source and untouched JSON samples are in this directory.

The median wall change is −12.69% and the median peak RSS change is −76.42% for this single large-file fixture. The baseline wall observations span 15.566 ms; changed observations span 0.527 ms. The changed process's resident memory after opening was *higher* (median 23.016 MiB versus 9.078 MiB), so the result is specifically about **peak** memory and construction time, not retained-state memory. `peak_build_admitted_bytes` is a scheduling estimate, not an allocation count or process-memory bound.

Every run had one file, 8,192 records, 8,192 successful parses, zero failed parses, four configured workers, 114 normal raw gram columns and 123 skip columns. The FNV-1a signature covers file path/revision/status/diagnostic counts, record identities/slots/ranges/classes, and raw/fallback normal and skip gram memberships. It is a semantic comparison fingerprint for this fixture, not a cryptographic proof of all repository state. The separate bounded/whole-buffer tests compare malformed diagnostics, posting maps, gram maps, record order and snapshot restore. Query record-batch parallelism was not changed or measured here.
