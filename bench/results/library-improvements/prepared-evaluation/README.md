# Prepared evaluator allocation check

This is a focused comparison of the pre-Q6 library at `b6d624ea574c51a83819441baf81263b2cdb72f1` and the Q6 implementation at `50760c9d0a4a95554b08e72d58ea7b2bc45e19a2`. The [standalone harness](harness/src/main.rs), [lockfile](harness/Cargo.lock), and generated fixture were identical in both detached worktrees. The production library was not edited for this measurement.

## Setup and commands

- Machine: `work`, 32 available logical CPUs; Rust `1.99.1 (58cf8f9c3 2026-10-13)`; Cargo release profile, default release flags. `RUSTFLAGS`, `CARGO_PROFILE_RELEASE*`, `CARGO_BUILD_TARGET`, and `CARGO_TARGET_DIR` were unset.
- Synthetic corpus: 32 `entries` and 128 `mentions` JSONL records in two files, generated by the harness. FNV-1a byte fingerprint: `1c3c8e395483961f` in both runs.
- Repository: ASCII bigrams, one build worker, one query worker, disabled snapshots and inference, 4 MiB prepared cache, disabled verified cache. Queries request exact counts, a 12-row locator page, and the stated evidence mode.
- Direct FILTER cases bind once, warm ten evaluations, then measure nine samples of 1,000 evaluations each. Repository cases validate optimized versus independent reference answers, warm three searches, then measure nine one-search samples. The baseline executable ran before the final executable. Builds and samples did not overlap.

The final worktree first compiled with `cargo build --release --manifest-path .../harness/Cargo.toml`, which generated the committed lockfile. That lockfile was copied unchanged to the baseline worktree, which compiled with `--locked`. For reproduction, use the following in each worktree, with the same `harness/` directory copied to `bench/results/library-improvements/prepared-evaluation/`:

```sh
cargo build --release --locked --manifest-path bench/results/library-improvements/prepared-evaluation/harness/Cargo.toml
```

Then run the built binary from that worktree root, saving stdout as the corresponding `baseline-b6d624ea.json` or `final-50760c9d.json` in this directory and stderr as the matching `.stderr.log`:

```sh
./bench/results/library-improvements/prepared-evaluation/harness/target/release/objekte-prepared-evaluation-allocation-harness
```

The harness wraps `System` with an atomic counting allocator. “Calls” counts `alloc`, `alloc_zeroed`, and `realloc`; “bytes” sums requested sizes, including the full new size of each reallocation. These are gross allocation requests across all threads during the measured operation. Deallocation is excluded, so bytes are neither retained heap nor RSS. Each table cell is the median of nine raw samples in the linked JSON files. Times are milliseconds, shown only as context; one sequential process per revision does not establish a stable speedup.

| Case | Evaluations/sample | Calls before → after | Requested bytes before → after | Median ms before → after |
| --- | ---: | ---: | ---: | ---: |
| Scalar equality | 1,000 | 2,000 → 2,000 | 36,000 → 36,000 | 0.068 → 0.067 |
| Scalar wildcard | 1,000 | 5,000 → 2,000 | 148,000 → 36,000 | 0.152 → 0.096 |
| Array wildcard | 1,000 | 6,000 → 3,000 | 180,000 → 68,000 | 0.174 → 0.113 |
| Local selected FTS, membership | 1 search | 2,283 → 2,123 | 239,570 → 231,314 | 0.067 → 0.062 |
| Local selected FTS, evidence | 1 search | 2,295 → 2,295 | 240,722 → 240,754 | 0.067 → 0.074 |
| Mixed relation/local FTS, membership | 1 search | 17,861 → 6,405 | 1,347,731 → 620,019 | 0.557 → 0.243 |
| Mixed relation/local FTS, evidence | 1 search | 17,873 → 8,657 | 1,348,883 → 817,011 | 0.555 → 0.378 |
| Mixed relation/local FILTER, membership | 1 search | 2,274 → 2,274 | 514,725 → 514,885 | 0.113 → 0.189 |
| Mixed relation/local FILTER, evidence | 1 search | 2,352 → 2,352 | 519,432 → 519,592 | 0.110 → 0.112 |

All nine baseline/final result signatures match. The wildcard cases show fewer allocation requests in direct bound evaluation. Mixed relation/local FTS shows fewer requests in the warmed repository call, consistent with removal of per-field binding clones and evidence-free short-circuiting. The harness counts whole search operations, so its numbers do not assign every request or byte to a particular helper. The mixed FILTER cases show no allocation-call reduction; their small byte differences and unstable times are not evidence of an improvement.
