# Predicate ordering benchmark evidence

Baseline engine: `a68cb0c67b68987251d35f528ccbbe3445509ea1`. Final engine: `49e82e881c5d`; final benchmark harness revision: `ba418374641a`. The extended 194-query Musenalm corpus, four workers, ASCII/Unicode indexes, and cache-off/64 MiB-warm profiles are the same in `baseline-suite/` and `acceptance-suite/`. Each query/profile has three timed samples. `acceptance-suite/result-digests.json` and `baseline-digest-audit/result-digests.json` hash complete ordered hit objects, including payload and evidence, and match for all 194 queries.

The audit baseline was compiled from the predecessor core with the later result-digest-only harness copied into the detached worktree. Its `run-manifest.json` correctly records the predecessor checkout. The audit's `workload_fingerprint` differs because the existing `hash_paths` function includes the absolute worktree path; the extended manifest file SHA-256 and parsed `queries.json` are identical. The baseline benchmark binary SHA-256 was `84f7d389effe5f74464bfb5ff42a090ee8fe81759f3a8b917f804d10e4e0a6f3`; the acceptance binary was `89d1593a41242a70a7d9d2a77f0822913bb1e488b1feb0af7bcc360667094d94`.

`fixture-v2/manifest.json` records the deterministic 1,000-record fixture generated by `bench/generate_predicate_fixture.py`. `focused-acceptance-*.jsonl` contains 21-sample warm-up-then-timed cases in baseline/final/final/baseline order. The harness checks complete results against `search_reference` on every sample and records min/median/max, counters, and selected order. Fixture record files and compiled binaries are generated artifacts and are not committed.

`acceptance-recheck-*/` contains the alternating seven-sample recheck of the 58 cases flagged by the corrected full suite; `acceptance-deep-*/` contains 21 samples for the remaining 11 distinct cases; `acceptance-isolation-*/` contains the final Q012 check in reversed order. The recheck manifests were run from their respective baseline or final worktrees, so their revision fields identify the actual engine. `preliminary-final/` records the pre-fix full-suite CSV and manifest; `preliminary-isolation/` records the old Q174/Q182 isolated CSVs. These document the avoidable per-record cleanup found and corrected in `49e82e88`. Other preliminary and local build logs are omitted.

The full command pattern is:

```sh
<binary> --root /home/simon/source/objekte/examples/musenalm --extended \
  --profiles ascii-off,ascii-warm,unicode-off,unicode-warm \
  --repetitions 3 --query-workers 4 --verified-cache-bytes 67108864 \
  --result-dir <output>
```

For rechecks, `--cases` took comma-separated IDs from `acceptance-recheck-cases.txt` or `acceptance-deep-cases.txt`, `--profiles ascii-off,unicode-off`, and `--repetitions 7` or `21`. The isolated Q012 run used `--cases Q012 --profiles ascii-off --repetitions 21`.
