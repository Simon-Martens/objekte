# Musenalm regression checks

Run these commands from the repository root. Each command writes a separate result directory under `bench/results/musenalm/`; pass `--result-dir` to choose another directory.

For focused planning comparisons, `bench_musenalm` accepts `--cases Q035,Q141`, `--repetitions 7`, and `--prepared-cache-bytes 0` (default: 16 MiB). The prepared-cache setting is recorded in `run-manifest.json`; keep it identical across compared binaries. `--verified-cache-bytes 0` disables verified-result reuse independently.

| Check | Command | What it verifies |
|---|---|---|
| Independent oracle | `python3 bench/verify_jq_oracle.py --result-dir bench/results/musenalm/jq-oracle-local` | `jq` evaluates 150 explicit predicates over all 148,486 original JSON files. The core returns complete ID sets under ASCII and Unicode. All 300 sets must agree. Pass `--save-membership` to retain full gzip membership files; per-case SHA-256 digests are always saved. |
| Fast iteration | `python3 bench/run_query_regressions.py quick --comparison repair --baseline bench/results/musenalm/controlled-foundation-performance-92cdb92b19` | One uncached ASCII run of all 150 cases. Checks sample count, status, exact count against the independent `jq` baseline, page size against the selected baseline, resolved workload/schema, corpus identity, environment, and latency budgets. |
| Full query gate | `python3 bench/run_query_regressions.py full --comparison repair --baseline bench/results/musenalm/controlled-foundation-performance-92cdb92b19` | Five repetitions under each of ASCII uncached, ASCII warmed, Unicode uncached, and Unicode warmed: 3,000 samples. The same checks apply with tighter latency budgets. |
| Index builds | `python3 bench/run_build_regressions.py --comparison repair --baseline bench/results/musenalm/controlled-foundation-build-performance-92cdb92b19` | Three fresh processes for each of ASCII/Unicode with snapshots disabled/rebuilt. Checks complete single-parse builds and compares wall time, peak RSS, and snapshot size to the policy-matched foundation baseline. |

Every gate selects a named comparison and explicit baseline. The repair comparison uses the immediate pre-repair foundation revision `92cdb92b19`. The original [`final-92cdb92b19`](results/musenalm/final-92cdb92b19/) and [`build-92cdb92b19`](results/musenalm/build-92cdb92b19/) recordings used the `powersave` governor. The controlled [`query`](results/musenalm/controlled-foundation-performance-92cdb92b19/) and [`build`](results/musenalm/controlled-foundation-build-performance-92cdb92b19/) recordings used the later `performance` governor. Select a baseline matching the current CPU policy; the gate rejects a mismatch. For the long-term historical gate, use `--comparison historical --baseline bench/results/musenalm/full-128a7601c2` for queries or `--comparison historical --baseline bench/baselines/musenalm-build.json` for construction. The gate records both code revisions and checks resolved queries, semantic registrations, corpus/schema identity, profiles, worker/cache settings, compiler, hardware, governor, and affinity. A quick-run timing breach triggers three targeted repetitions; only a confirmed median breach fails the gate. The `jq` count baseline is [`musenalm-jq-counts.json`](baselines/musenalm-jq-counts.json). Fresh result directories are required because benchmark measurement files are created exclusively.
