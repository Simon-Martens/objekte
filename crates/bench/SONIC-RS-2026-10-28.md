# Sonic-rs integration

The library now parses source records, schemas/configuration, JSON filter values,
and cached page payloads with sonic-rs 0.5.10. Both compared release binaries use
`-C target-cpu=native`. Fingerprint serialization and the public/schema value
representation remain unchanged; the existing format-2 application cache is reused.

## Comparison on Musenalm

Three fresh processes per collection, mode, and implementation, interleaving the
saved Serde binary and updated Sonic binary. Each returns the default 50-row view.
The existing disk cache is a copy on Btrfs; source filesystem caches are warm and
uncontrolled. Compilation and Cargo startup are excluded. All returned rows and
view fingerprints match. No source files were changed.

| Cached view | Previous query/row stage | Sonic query/row stage | Previous whole CLI | Sonic whole CLI |
| --- | ---: | ---: | ---: | ---: |
| `contents` | 1.392 ms | 1.394 ms | 0.4194 s | 0.4160 s |
| `entries` | 11.856 ms | 5.317 ms | 0.0348 s | 0.0285 s |

Values are medians. Every cached run reports one manifest hit and zero source-file
reads. `query_nanos` includes SQL, fetching page payloads, decoding, and building
rows, so this is not a parser-only microbenchmark. The `contents` CLI remains
dominated by its metadata inventory. Large nested `entries` records benefit from
decoding only the fields needed for the page.

| Full source view (`--cache disabled`) | Previous whole CLI | Sonic whole CLI | Previous parse/validate stage | Sonic parse/validate stage |
| --- | ---: | ---: | ---: | ---: |
| `contents` | 4.8449 s | 5.0063 s | 1.2770 s | 1.4965 s |
| `entries` | 1.8655 s | 1.9681 s | 1.3578 s | 1.4618 s |

Full source views are approximately 3–6% slower in this comparison. They still
materialize every complete record for schema validation and relationship extraction.
The Sonic document is converted into the existing `serde_json::Value` representation,
which adds work. These measurements do not establish a faster initial cache build;
they demonstrate the cached-page improvement and the full-record conversion tradeoff.

## Compatibility and implementation

- Full parsing uses Sonic's arbitrary-precision representation. Numeric text is
  converted into the existing public number type without passing through `f64`.
  Object members are processed in source order, preserving last-member-wins
  behavior, including escaped and nested duplicate keys.
- Cached pages use a runtime field selection compiled from requested columns and
  the display field. Sonic scans all top-level members, materializes selected
  values, and skips other payloads. This is generic and introduces no persisted
  projection cache or Musenalm-specific record structs.
- Sonic's fast skip accepts unpaired UTF-16 surrogate escapes. Skipped values
  containing `\u` therefore receive a full Sonic validation pass. Invalid values
  and trailing input remain errors, including in unselected fields.
- Source/schema parsing retains the previous nesting limit. JSON Schema validation,
  numeric-domain checks, SQLite index values, and persisted fingerprint bytes keep
  their existing contracts. Source JSON text remains authoritative and unchanged.

The regular core/CLI suite passes 95 tests, including seven new parser/integration
tests. They cover precise numbers, duplicate keys, Unicode, missing/null projection,
large skipped payloads, malformed cached payloads, and relationships/indexes built
from duplicate fields. Release Clippy passes with warnings denied.
The complete Musenalm acceptance passes in 81.70 s: all 148,486 records, 173,427
reference occurrences, direct/SQLite queries, secondary sorts, and metadata/strict
reopens. Its local report is `target/sonic-profile/musenalm-acceptance.json`.

## Reproduce

```sh
cargo build -p objekte-cli --release
target/release/objekte examples/musenalm view entries --data-dir target/disk-cache-profile --diagnostics
target/release/objekte examples/musenalm view contents --data-dir target/disk-cache-profile --diagnostics
target/release/objekte examples/musenalm view entries --cache disabled --diagnostics
cargo test -p objekte-core -p objekte-cli --release
```

An empty application directory first builds a cache; exclude that run from cached
measurements. Local raw results are in `target/sonic-profile/comparison.json` and
the saved previous binary is `target/sonic-profile/serde-json-native` (both ignored).
