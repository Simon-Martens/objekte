# Stage 1: logical records and lifecycle

Starting source revision: `4cea642f82904b83a3676eb87731a198c746788e` (clean). The release reference binary is preserved in the ignored `reference-bin/` directory; its SHA-256 and the unchanged 148,486-record Musenalm corpus fingerprint are in [baseline-manifest.json](baseline-manifest.json). The [reference](reference/) directory contains validated 152-case, seven-round ASCII runs for 0 and 64 MiB query-cache budgets. Both runs completed before production edits.

The review findings were reproduced in source: the Sonic and serde JSON adapters had only scalar `visit_leaves`; `rebuild_text_index` used a frozen selected inventory; `refresh` could invalidate freshly built selected postings; selected derived queries required postings after a no-op warm under disabled or hash freshness; native derived cache lookup cloned all slots and published before page validation; selected routing scanned source descriptors; and automatic selected indexing propagated malformed native JSON parse errors that ordinary field search excludes.

This stage emits parent-before-child logical nodes from both built-in JSON adapters; freezes the custom-source routing fact in each snapshot; uses binary search for selected IDs; refreshes before explicit text rebuilds; reconciles selected postings after native picker updates; retains explicitly active selected text specs; uses a direct derived route and direct distinct counts when a posting is unavailable by policy; aligns full derived totals; slices native derived cached pages and delays publication until validation; and treats only malformed *built-in filesystem JSON* as unindexed during selected projection. Custom decoder and callback errors still propagate.

Focused downstream tests in `review_stage1.test.rs` compare native JSON with the same custom-provider JSON, including root arrays, empty containers, numeric keys, escaped keys, filters and extracted values. They cover disabled/memory caching, all freshness modes, count caps, malformed JSON, explicit rebuild after additions/edits, and retention of selected postings after a native edit. The existing 32 downstream tests and workspace tests passed; Clippy with `-D warnings` passed. The full query benchmark comparison is reserved for the final production code, as requested.
