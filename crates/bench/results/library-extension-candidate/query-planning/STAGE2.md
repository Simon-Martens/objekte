# Stage 2: mixed-source candidate planning

Parent revision: `35dbf96548`. This stage adds generation-bound native-to-selected slot mapping and retains custom slots as the fallback domain when a native posting is used. Configured logical scalar fields now use the existing typed/presence index across selected records, built in the same selected-source pass as text and derived projections. Ordinary warm/save/reopen restores these field postings; the selected manifest is version 2 and incompatible older selected posting metadata rebuilds. Native JSON snapshot bytes are unchanged.

Selected JSON queries use typed/presence necessary conditions over a complete selected posting when available, or translate native picker candidates and include custom slots. Unknown AND terms remain residuals; unsupported OR branches broaden the domain. Text queries union compatible field representation candidates and combine them with scalar constraints. A rare scalar term can be the sole candidate seed; a rare text term can instead be the seed. Exact predicate evaluation remains in source order. Candidate sets are only used when cardinality/error checks and representation compatibility allow pruning. Generation-bound default order and rank avoid sorting the full selected inventory per query; sparse candidate enumeration visits only set bits.

`review_stage2.test.rs` compares complete indexed and direct results across a mixed collection and a separate native collection. One custom record does not disable the native posting; the selective query reads fewer than 20 sources while the direct oracle reads at least 193. It tests an unsupported OR branch, a deep completed-cache page with exactly three descriptor visits and source reads, opposite scalar/text seeds, multiple text fields, and field-posting save/reopen. The focused tests and Clippy passed. Remaining incremental selected-posting work is tracked in Stage 3.

Follow-up after Stage 3: cheap B-tree posting cardinality estimates now defer broad scalar bitset materialization when a selective text posting can drive verification. The downstream reversed-selectivity fixture asserts one scalar bitset for the rare-scalar case and zero for the rare-text case. This is a bounded heuristic, not an exhaustive optimizer.
