# Stage 3: generation work, incremental postings, and selected streams

Parent revision: `5fa07ccf49`. Generation-bound default order/rank, sparse candidate enumeration and completed-cache page slicing now avoid per-query full selected-source sorting and full match-list copying. Selected query metrics expose candidate and descriptor visits. Nonreturned selected candidates skip content-digest computation; returned records retain their revision check and digest.

A small refresh delta remaps unchanged typed posting rows from retained old index state, then reads and decodes changed records once for all active field and derived outputs. Immutable text postings retain their base filter with a base-to-current slot map and a conservative changed-record overlay. The overlay is verified by exact matching; deleted slots are not live. When the delta or accumulated overlay exceeds one quarter of the collection, or semantic/posting compatibility fails, the selected postings rebuild. Discovery may still enumerate all provider sources; remapping existing typed rows is collection-sized in-memory work. The refresh target is changed-record-proportional source decoding, not constant-time discovery or CPU work.

Selected text companion manifest version 5 persists the overlay, mapping, base source signatures and payload digest. Restore rejects incompatible versions and invalid slot mappings; native JSON snapshot bytes remain unchanged. `review_stage3.test.rs` verifies one edit with active text, field and derived postings reads/parses one source; delete and rename avoid decoding unchanged sources; save/reopen restores without source reads; a corrupted mapping triggers a full rebuild. It also verifies unsorted selected JSON and text callback errors stop after at most two reads and publish no complete ordered entry. Sorted selected streams still prepare the bounded sort before delivery. The selected predicate path still builds an owned logical record per verified candidate; the native-only path remains concrete and fused.

Workspace tests and Clippy (`-D warnings`) pass. The final native query timing comparison is recorded separately in `REPORT.md` after this production commit.
