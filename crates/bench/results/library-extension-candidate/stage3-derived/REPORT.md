## Normal release measurements

The first full JSON mix ran all 152 loaded cases, seven rounds per process, three alternating reference/candidate pairs at each query-cache budget (0 and 64 MiB). All count/first-ID signatures and source scan/read/parse counts matched. The largest median paired increases were 3.81 ms cache off (case 118) and 3.31 ms cache on (case 114). Those runs preceded the restore decoder fix and the later extraction-buffer cleanup; their raw outputs remain in `json-paired-20261104/`.

The final source ran the original 50-case subset with the same seven-round, three-pair protocol and both cache budgets. All 50 signatures and all source work counts matched in every pair. Across cases the median of paired median deltas was +0.018 ms cache off and +0.011 ms cache on. The largest case median increases were +1.84 ms cache off (case 42) and +1.97 ms cache on (case 50). Every per-case sample is in `final-json-50-paired/`; this targeted rerun does not replace the final full 152-case gate.

The first candidate restored seven cached indexes in about 600 ms versus about 530 ms for the reference. The detailed counting-allocator profile isolated roughly 50 ms of that gap to secondary bincode structure decode; snapshot bytes, allocation count and peak memory were effectively equal. The compiler had inlined `BufReader::read_exact`'s slow fallback into a read called repeatedly during decode. `ExactReader` now keeps the buffered common path small and sends rare cross-buffer reads to a cold helper. Five alternating normal release samples after the final source changes had medians of **527.14 ms reference** and **531.79 ms candidate** (paired samples in `final-warm-*`). Five detailed restore samples after the fix had medians of 315.09 ms for the preceding stage and 309.78 ms for this stage; one 435.86 ms candidate outlier is retained in `fixed-restore-summary.json`.

The normal release Musenalm FTS4 build used the same benchmark-only driver and source paths on both revisions, with one warmup and five alternating pairs. Medians were **1,492.24 ms reference** and **1,477.99 ms candidate**; each built 133,948 documents and 47,456,174 compressed index bytes. Raw outputs are in `final-index-build-fts4-normal/`. The counting-allocator plus stage-timer build remains a separate diagnostic: it showed a larger baseline/candidate gap, as in the preceding stage, but a same-session comparison with the preceding instrumented candidate was faster in median. It is not used as a proxy for normal release latency.
