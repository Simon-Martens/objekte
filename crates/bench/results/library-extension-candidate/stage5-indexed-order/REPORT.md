# Selected derived order stage control

## Source and measurement

This stage starts at `15bac840b4` on `library-extensions-stage2-wip`; implementation is committed as `81426c3f47`. The change adds a lazy, scalar-safe order over the selected provider posting; it keeps exact predicate verification in source order and rereads returned page records. The measured release binaries were built before formatting-only edits. Their SHA-256 values are `9f9e7b93a29ba41b0018f8fa758375bc35b47b12bbe6e93eb964a9803dc573ca` (previous JSON), `012dd9babeb0ba9a446eef0b4bc1704cb888b4603fd9d38cc51deddc38812780` (candidate JSON), and `efab4999e424ce2bea6fddfc391d616a151cf6264d29e3f2d1e062567d4201f7` (candidate example). Executables are preserved in ignored `candidate-bin/` directories and are not committed.

The paired JSON control used the same pinned Musenalm paths and metadata as Phase 0: 148,486 records, 193,297,230 bytes, source/content/stat SHA-256 `90e36ad63dcb6386e9521c583fdcd36451fd3d6182187dced542fb8292f730ce`, and 50-case workload SHA-256 `d7e6967dc1250cf28c054027c72fba8452f5ccd4e8fe3eea9653423fa135e7d7`. Commands, binary hashes, exits, stdout, stderr and every sample are under `json-50/` and `case42-paired/`. The former used three alternating process pairs with seven measured rounds per process; the latter used five alternating pairs with 15 rounds on one case. Both used `RAYON_NUM_THREADS=16`, CPU affinity 0–15, ASCII bigrams, and separate 0/64 MiB cache budgets. Filesystem caches were warm and not evicted.

The extension control used `RAYON_NUM_THREADS=16 taskset -c 0-15 target/release/examples/frontend_derived_compare 7 sort` and the same command without `sort`. It generated 20,000 JSON and 100 Markdown files before timing; their filename/content SHA-256 was `436463c8fb0fef71587b186d716b658c3955e48388f9f13daf7ae96c2dde88bd`. Scan and indexed repositories used the same temporary paths and metadata in one process, zero query-cache budget and seven alternating measured rounds. `frontend-lazy-*.json` contains the full ordered IDs and every sample. `frontend-*.json` without `lazy` is exploratory eager-order data; that version was replaced because it added work to unsorted posting builds.

## Results

For the sorted extension query, all 200 ordered IDs, count and truncation agreed with the scan. The lazy derived-only build took 144.822 ms and the fused text-plus-derived build took 153.326 ms with exactly 20,100 reads and parses. First sorted indexed warmup took 5.073 ms, including order construction. The seven scan samples had median 136.697 ms and range 134.379–137.165 ms; indexed samples had median 1.719 ms and range 1.617–1.856 ms. Reads and parses were 20,101 versus 201 per query. Unsorted derived-only build took 145.217 ms, fused build 154.499 ms, scan median 135.784 ms and indexed median 1.877 ms. This is a targeted control, not a full build-profile comparison.

All 50 default JSON case signatures and scans/reads/parses matched for every pair and both budgets. With cache off, the median case delta (candidate minus prior stage) was +0.019 ms; the largest positive median of paired medians was +1.951 ms for case 42, `contributors:length > 0`, against a 114.123 ms reference median. With 64 MiB cache, the median case delta was -0.003 ms; the largest positive was +0.780 ms for case 50 against 117.784 ms. `json-50/summary.json` gives every case and paired delta.

Case 42 was isolated and repeated. With cache off, reference median was 115.440 ms and candidate median 116.487 ms; paired deltas were +0.484, +1.253, +1.040, +0.751 and +1.935 ms, median +1.040 ms (about 0.9%). Reads, parses and scans remained equal. With 64 MiB cache, medians were 9.403 and 9.395 ms and median paired delta was +0.003 ms. The small cache-off difference is reproducible and remains recorded; this control does not identify a change in work or prove its cause. It is within the user's stated tolerance for small absolute differences, without a general abstraction-overhead allowance.

## Correctness and remaining scope

The external consumer test compares ascending and descending scan/index order across exact numeric values, ties, null, missing, no value, and mixed JSON/Markdown sources. It checks offsets, page values, count caps, truncation, ordered-cache reuse, returned-page reads, and refresh invalidation followed by rebuild. Multi-valued sort fields retain the heap and its cardinality error. `cargo test --locked --workspace --all-targets -q`, `cargo clippy --locked --workspace --all-targets -- -D warnings`, and `cargo test --locked -p objekte-bench --features index-timings,allocation-profile --all-targets -q` passed. Changed Rust files pass rustfmt and `git diff --check`. Whole-workspace spacing still fails on the same seven pre-existing hunks in five untouched files; logs are saved here.

Selected provider postings and orders remain process-local, absent from snapshots. Custom provider records remain outside legacy picker queries. The full Phase 0 benchmark matrix and large-corpus source-oracle runs are still open; this stage alone does not establish final acceptance.
